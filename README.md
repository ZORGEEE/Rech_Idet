## Проект для обучения РКИ

### Архитектура проекта

Проект использует модульную архитектуру с разделением на слои:

```
Speech_Goes/
├── config/              # Конфигурация приложения
├── database/            # Работа с базой данных
│   └── repositories/    # Репозитории для доступа к данным
├── models/              # Модели данных
├── services/            # Бизнес-логика
├── api/                 # API endpoints (Blueprint)
├── web/                 # Web routes (Blueprint)
├── utils/               # Утилиты (сериализация и т.д.)
├── bot/                 # Telegram бот
│   ├── client.py        # Клиент для работы с API
│   └── handlers.py      # Обработчики команд бота
├── app.py               # Главный файл Flask приложения
└── telegram_bot.py      # Запуск Telegram бота
```

### Инструкция по запуску

#### 1. Активируй виртуальное окружение
```bash
source rech_idet/bin/activate
```

#### 2. Установи зависимости
```bash
pip install -r requirements.txt
```

#### 3. Проинициализируй базу данных
```bash
python3 init_db.py
```

#### 4. Настрой переменные окружения (опционально)
```bash
export DATABASE_PATH=database.db
export API_BASE_URL=http://127.0.0.1:10000/api
export TELEGRAM_BOT_TOKEN=your_token_here
export FLASK_HOST=0.0.0.0
export FLASK_PORT=10000
```

#### 5. Запусти Flask приложение
```bash
python3 app.py
```

Или с помощью gunicorn:
```bash
gunicorn app:app --bind 0.0.0.0:10000
```

#### 6. Запусти Telegram бота (в отдельном терминале)
```bash
python3 telegram_bot.py
```

#### 7. Остановка
- Для остановки сайта: `Ctrl + C`
- Для остановки бота: `Ctrl + C`

#### 8. Деактивируй виртуальное окружение
```bash
deactivate
```

### Структура модулей

- **config/**: Централизованная конфигурация приложения
- **database/**: Подключение к БД и репозитории для работы с данными
- **services/**: Бизнес-логика (поиск, фильтры)
- **api/**: REST API endpoints для внешних клиентов
- **web/**: Веб-роуты для HTML страниц
- **bot/**: Telegram бот, использующий API для получения данных
- **utils/**: Вспомогательные функции (сериализация)

### Преимущества новой архитектуры

1. **Разделение ответственности**: каждый модуль отвечает за свою область
2. **Переиспользование кода**: логику можно использовать в API и боте
3. **Тестируемость**: легко писать unit-тесты для каждого модуля
4. **Масштабируемость**: легко добавлять новые функции
5. **Поддерживаемость**: проще находить и исправлять ошибки
